# Bonnes pratiques pour le projet ChessMate ✨

---

## ✏️ Normes de codage
- Code et documentation doivent être en français.
- Noms de variables en `camelCase`
- Noms de constantes en `UPPER_SNAKE_CASE`
- Noms de fichiers en `PascalCase`
- Noms des classes en `PascalCase`
  - Noms d'attributs en `camelCase`
  - Noms des propriétés en `PascalCase`
  - Noms des méthodes en `camelCase`


- Utiliser des commentaires clairs et concis
- Respecter les conventions de style de Java (indentation, espaces, etc.)

## 🕐 Gestion des versions
- Ecrire des commits clairs et descriptifs
- Créer des branches pour chaque nouvelle fonctionnalité ou correction de bug
- Faire des pull requests pour faire réviser le code par quelqu'un d'autre avant de le fusionner dans la branche principale
- Les commits doivent être écrits sous la forme suivante :
`<type> - <scope>: <subject>`
  - `type` : type de changement (feat, fix, docs, style, refactor, test, chore)
  - `scope` : partie du code affectée (optionnel)
  - `subject` : description courte du changement (impératif, pas de point à la fin)
